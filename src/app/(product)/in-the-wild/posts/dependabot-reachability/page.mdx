### What shipped

On October 28, 2026, GitHub [announced reachability analysis for Dependabot alerts](https://github.blog/changelog/2026-10-28-prioritize-dependabot-alerts-with-reachability-analysis/). In public preview for JavaScript and TypeScript, it looks for call paths from your code to vulnerable functions in dependencies. Alerts can be **reachable**, **potentially reachable**, **unreachable**, or **reachability unavailable**.

That verdict adds context for prioritizing work alongside severity, EPSS, and what you know about your application. It doesn't dismiss alerts for you: reachable doesn't necessarily mean exploitable, and unreachable isn't a guarantee that a dependency is safe.

### The problem

A verdict is a starting point, but the path helps answer *why*. To investigate an alert, a developer needs to see how code in their repository connects to a vulnerable function, one step at a time. A path can move through repository code, packages, and direct or transitive dependencies. If those steps all look alike, it's harder to see where to start looking. Where the evidence is incomplete, the interface shouldn't make an endpoint look more certain than it is.

### Where I fit in

Product designers shaped the call-path investigation experience on Dependabot alerts. I worked closely with them, primarily implementing the UI while contributing to key design decisions about how to present and navigate the evidence. The broader team built the analysis and verdicts; my work was on the alert-side experience:

- **Follow the chain.** Working with the designers, I helped decide how repository, package, and function steps, including direct and transitive dependencies, should read together, then implemented that hierarchy in the UI.
- **Read the relevant code.** I implemented compact, highlighted snippets from repository code and an action to open the source file. Together we made the vulnerable function easier to spot on a complete path without making an incomplete one look certain.
- **Stay oriented.** I polished step transitions and previous/next navigation in code, including keyboard focus and reduced-motion behavior as the path changes.
